# Produce Court Filing

## Context

Use to produce or render a court-ready motion, complaint or other filing in the litigant's own matter. Apply the legal constitution's Standing constraint. Use the jurisdiction profile and the court filing pipeline for a court PDF. The ordinary PDF and legacy hand-edited Word motion template paths are outside this workflow.

Classifier seam: none.

## Objective

Deliver the validated court artifact in the matter's visible filings directory, with scratch sources and review evidence in its dedicated build directory. Keep production, human approval and confirmed filing as separately evidenced states.

## Inputs

- `<user_request>` identifies the matter, document, format and planned date of filing or service.
- `<context>` names the matter `AGENTS.md`, court, jurisdiction profile, build and output paths, applicable page or word limit, and any planned submission or service route.
- `<source_material>` includes approved substantive `body.md`, structural `caption.json`, the current citation report, final attachments with the Verify Citations cited-attachment manifest (possibly empty), and authoritative caption and service sources. When something is missing, obtain it through the relevant drafting workflow before the dependent step.

## Steps

### What can proceed on this entry?

Before dependent work, request `preflight` from [Litigation Counsel](../../experts/Litigation%20Counsel/EXPERT.md) with this skill's name, the planned work, and the available matter or intake record. Reuse its current result only for the same issue, action and facts. On `proceed`, apply the returned practice-area prerequisites. On `hold`, record the reason and resolution needed, and limit work to independent preparation or a clearly held draft. On `stop`, end the affected work. Ask for missing facts that determine any unresolved trigger or ordering requirement. Apply this step on direct entry and when separate owner review is declined. Recheck when new information changes a trigger, posture or prerequisite.

### What clears the requested artifact?

1. **Read the contracts and stage inputs.** If a preflight hold applies to production, return the held draft and its blocker. For production that can proceed, run Maintain Matter File in preflight mode. Load `legal` tool `Court Filing` and `wiser` tool `render`. Read command usage and setup from their contracts, including dependency and consent stops in `wiser/AGENTS.md`. Which court and document profile applies? Use its schema, caption defaults, formatting, filing packet and any current court instructions. Run `node scripts/court-filing.js profiles` in Court Filing and read its `profiles` array. Use `colorado-district` only for the confirmed Colorado district court route. If that profile or required rule is missing or conflicts with the court, hold and resolve it before composing. Check the applicable page or word limit against Motions Practice's checklist or the current court rules. The Colorado general motion limit in the source was 15 pages under C.R.C.P. 121 section 1-15(1)(a) `[verify]`. Apply only the confirmed limit for the actual filing type and court. Keep sources, reports, HTML and PNG previews in a portable dedicated build folder under the matter's filings directory. The visible filings directory is the output location. Use `YYYY-MM-DD - <Document Title>.pdf` with the planned filing or service date. Reserve a `DRAFT - ` prefix for an editable working source, such as Markdown. Never overwrite a filed document.
2. **Clear substance, caption and citation.** Keep argument, facts, citations, conferral when required and prayer in `body.md`. Use `caption.json` for fields such as court and address, party roles and names, exact case number, division, document title, signer name, role and contact lines, and service method, signer, recipients and firm details when applicable. Take field names, requirements and defaults from the selected profile. Reconcile parties and dates with the docket and orders, and the firm and service information with counsel's latest filing or communication. Hold for any required discrepancy or missing field. When the docket has assigned case and division values, use those exact values. When an initial filing has unassigned values, use a placeholder only if current court instructions accept it and the profile can render and validate it. If the court requires a blank that the caption schema cannot express, hold this production path. Which service fields apply? Use `service` when the selected court and filing require a certificate. For a verified filing type carrying no certificate, use `no_service_certificate` with exactly one listed profile reason ID, without a `service` block. Record the source and why it applies. If applicability is unverified or no reason matches, hold. Leave signature and required service dates to the signer. Is citation clearance current? Match the exact `cleared` value, `full` scope, current body path and SHA-256, and each cited attachment's identifier, original path, SHA-256 and complete coverage to the manifest and actual submission inputs. Compare the manifest to the draft references and final attachments. If the current report is `held`, carry its holds forward and rerun only when corrected text, an updated attachment, or new authority addresses a finding. For a missing, incomplete or stale report, run Verify Citations on the exact body and manifest with originals and any readable companion text. Hold production until there is a matching clearance and no unresolved `[verify]`. Confirm the litigant has approved the substantive version for rendering.
3. **Compose, render and validate, in that order.**
   1. From Court Filing run `node scripts/court-filing.js compose --body <body.md> --caption <caption.json> --profile <id-or-file> --out <fresh.html>` with absolute file arguments. Keep the resulting `html`, `profile`, `pdf`, `pdfArgs` and `footerFont`.
   2. From the `wiser` tool `render` run `node scripts/render.js pdf --input <html> --output <fresh.pdf>` and append `pdfArgs` unchanged as individual arguments. Require a successful run with `output` at the intended path, `format` equal to `pdf`, and a concrete `pages` count. Keep the CSS page geometry and footer settings from the composition. If the renderer refuses the file, hold and resolve the named error before retrying.
   3. From Court Filing run `node scripts/court-filing.js validate --pdf <output> --caption <caption.json> --profile <id-or-file>` with the same caption and profile. For a verified preset pass `--limit <id>`. For verified explicit maxima pass `--max-pages <N>` and/or `--max-words <N>` instead. Pass `--body <body.md>` with the exact Markdown for a word limit. If no limit applies, record its verified inapplicability and omit limit flags. An unresolved limit holds the filing. Require exit 0, `ok: true`, and exactly `result: "ALL CHECKS PASSED"` for these inputs. Read `profile`, `pages`, `bodyWords`, `limits`, `checks` and `unavailable`. Require `pass` for every applicable check, including PDF readability, caption fields, signer, required certificate and service emails, page geometry, embedded profile fonts, footer and visible margins. Accept `not_applicable` only on the certificate check when its detail matches the approved profile reason. On failure, missing evidence, mismatched inputs or conflicting results, retain the result, hold release and repeat the dependent steps after correction. Changes to the text or cited attachments reopen citation clearance.
4. **Handle a required Word or official form.** Does the court or document require `.docx`? For a new Word artifact that fits the documented title-and-paragraphs format, use `node scripts/word-document.js create --input <json> --output <fresh.docx>` from `wiser`'s `word-document` directory. The UTF-8 JSON supplies `title` and `paragraphs`. Require a successful result with the intended canonical `output`. For a required caption table or other structure outside the create schema, use the court's official Word template or require a Word artifact that can meet those requirements. Hold if the prescribed structure cannot be produced or checked. Inspect the actual Word file and apply any court-mandated mechanical checks. For a filing, retain a mechanically validated court PDF proof using steps 2 and 3 and compare it with the Word submission, including caption, legal text, page structure and certificates. Hold release if equivalent content and applicable court requirements cannot be established. For a required official fillable form, obtain it from the issuing court, fill the original form and check its required fields and applicable packet rules. If Open a Matter handed over just the Colorado district civil complaint, return that artifact to it for JDF 601, JDF 600 and fee or waiver checks. For a direct request for that entire packet, route to Open a Matter. Use a legacy table caption only as a visual reference when supplied. Generate new motion PDFs with steps 2 and 3.
5. **Review the exact artifact with the litigant.** Rasterize PDF pages to PNGs in the build folder using available local PDF tooling, such as `pdftoppm -png`. Open the pages and visually check caption, spacing, page numbers, margins, exhibits, signature lines and the declared certificate treatment, including whether the finished filing correctly omits the certificate. If the preview cannot be produced or differs from the profile or draft, hold the filing and resolve it. Show the artifact and intended submission, recipients and attachments. The litigant signs and completes applicable blank signature and service dates immediately before filing in a PDF editor or by the court's accepted method. Verify the planned filename date against actual filing or service. If edits change the artifact, recheck it, mechanically validate the final PDF with the same command, caption, profile and applicable limit and repeat affected review before release. Never insert signature or service dates by automation.
6. **Record release and filing separately.** Apply the Litigation Counsel owner gate under `wiser/AGENTS.md` Precedence and routing before any filing-ready handoff, subject to its separate-review decline path. Carry any preflight hold even when that review is declined. Is the exact reviewed packet explicitly approved for transmission with all applicable gates passed? If yes, the litigant can file through the court's approved channel, including Colorado Courts E-Filing where applicable, or give a specific instruction to transmit the exact shown packet where permitted. If approval is absent, return the validated artifact for the litigant's review. A draft approval, a signature or a promised future approval cannot authorize transmission. After the litigant reports filing or supplies the court receipt, use Maintain Matter File to record the actual date and update the matter. Retain previews and build sources as scratch under the matter's retention rules.

## Pitfalls

- A vague document, conflicting jurisdiction, or unclear date needs clarification before rendering. A date slip calls for updating the visible filename and reviewing any date-dependent fields.
- Mechanical checks cover what the tool reports. Inspect what remains visual, including exact spacing and margin geometry, and escalate an unmet court requirement. Report tool or profile defects to their owning tool. Never patch the tool during filing production.
- Colorado's e-filing channel, a completed signature block and a preview can each exist before filing. Record filed status only when supported by confirmation.

## Success

The output path is visible and keeps any previously filed copy intact. The build record identifies the exact citation clearance, verified caption sources, compose and render inputs, validation result, preview review and human decision. No filing can be released with a held gate or recorded as filed without confirmation. Ask the litigant to report back after filing so the matter file can be updated.
