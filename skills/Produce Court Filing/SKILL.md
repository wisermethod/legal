# Produce Court Filing

## Context

Use to produce or render a court-ready motion, complaint or other filing in the litigant's own matter. Apply the legal constitution's Standing constraint. Use the jurisdiction profile and the court filing pipeline for a compatible court PDF. Use the forum’s stated format for a submission with no compatible profile.

Classifier seam: none.

## Objective

Deliver the validated court artifact in the matter's visible filings directory, with scratch sources and review evidence in its dedicated build directory. Keep production, human approval and confirmed filing as separately evidenced states.

## Inputs

- `<user_request>` identifies the matter, document, format and planned date of filing or service.
- `<context>` names the matter `AGENTS.md`, court, jurisdiction profile, build and output paths, applicable page or word limit, and any planned submission or service route.
- `<source_material>` includes approved substantive `body.md`, structural `caption.json`, the current citation report, final attachments with the Verify Citations cited-attachment manifest (possibly empty), and authoritative caption and service sources. When something is missing, obtain it through the relevant drafting workflow before the dependent step.

## Steps

Apply the [Handoff label](../../AGENTS.md#handoff-label) whenever this work returns an assessment, packet or draft to the person, including on an early return.

### What can proceed on this entry?

Before dependent work, request `preflight` from [Litigation Counsel](../../experts/Litigation%20Counsel/EXPERT.md) with this skill's name, the planned work, and the available matter or intake record. Reuse its current result only for the same issue, action and facts. On `proceed`, apply the returned practice-area prerequisites. On `hold`, record the reason and resolution needed, and limit work to independent preparation or a clearly held draft. On `stop`, end the affected work. Ask for missing facts that determine any unresolved trigger or ordering requirement. Apply this step on direct entry and when separate owner review is declined. Recheck when new information changes a trigger, posture or prerequisite.

### Which production path applies?

Check the forum’s orders, notices, submission instructions and required forms. When a compatible profile applies, run the court pipeline below. When no compatible profile exists, run Maintain Matter File, verify the exact body and cited attachments through Verify Citations, and reconcile the required submission and service facts against the primary record. If the matter supplies a format, fill the issued form or render to the documented specification with the appropriate local Wiser tool. Check each stated requirement against the exact artifact, including pages, fields, attachments, audience and signature or service treatment. Save the exact inputs, requirements, check evidence and preview for human review. If the format is absent, produce a clearly labeled review draft in the requested or an editable format. Name the fields, layout, limits, acceptance or other requirements that remain unverified. Keep filing readiness held on any missing required check and report the unavailable profile validation. Apply the same owner and human approval, release and filing-confirmation gates below.

### What clears a profiled artifact?

1. **Read the contracts and stage inputs.** If a preflight hold applies to production, return the held draft and its blocker. For production that can proceed, run Maintain Matter File in preflight mode. Load `legal` tool `Court Filing` and `wiser` tool `render`. Read command usage and setup from their contracts, including dependency and consent stops in `wiser/AGENTS.md`. Which court and document profile applies? Use its schema, caption defaults, formatting, filing packet and any current court instructions. Run `node scripts/court-filing.js profiles` in Court Filing and read its `profiles` array. Use `colorado-district` only for the confirmed Colorado district court route. If the selected profile conflicts with the forum or document, use the unprofiled path while resolving the applicable requirement. Select the working C.R.C.P. 121 section 1-15(1)(a) preset for the actual Colorado district motion class from Motions Practice and the profile. Confirm against the current rule and any order before filing, and use an applicable verified override where needed. If the document has no limit, record the controlling basis for that finding. Keep sources, reports, HTML and PNG previews in a portable dedicated build folder under the matter's filings directory. The visible filings directory is the output location. Use `YYYY-MM-DD - <Document Title>.pdf` with the planned filing or service date. Reserve a `DRAFT - ` prefix for an editable working source, such as Markdown. Never overwrite a filed document.
2. **Clear substance, caption and citation.** Keep argument, facts, citations, conferral when required and prayer in `body.md`. Use `caption.json` for fields such as court and address, party roles and names, exact case number, division, document title, signer name, role and contact lines, and service method, signer, recipients and firm details when applicable. Take field names, requirements and defaults from the selected profile. Reconcile parties and dates with the docket and orders, and the firm and service information with counsel's latest filing or communication. Hold for any required discrepancy or missing field. Use exact assigned docket values. For the profile’s declared new-case complaint packet use `filing_packet: "new_case_complaint"` and `case_number: ""`; confirm any pending division treatment with the court. The ordinary Colorado district caption requires `service`, including for complaints. Use the tool’s `proposed-order` or `supporting-declaration` mode only after reconciling the exact artifact to its controlling form and the enclosing packet’s service treatment. Check that a declaration retains its filer signature and that a proposed order carries only the unsigned judicial closing. For another profile, a no-certificate declaration requires an exact listed reason, the controlling source and verified facts. Hold for unresolved treatment, impermissible blanks or service facts that cannot be truthfully attested. Leave signature and required service dates to the signer. Is citation clearance current? Match the exact `cleared` value, `full` scope, current body path and SHA-256, and each cited attachment's identifier, original path, SHA-256 and complete coverage to the manifest and actual submission inputs. Compare the manifest to the draft references and final attachments. If the current report is `held`, carry its holds forward and rerun only when corrected text, an updated attachment, or new authority addresses a finding. For a missing, incomplete or stale report, run Verify Citations on the exact body and manifest with originals and any readable companion text. Hold production until there is a matching clearance and no unresolved `[verify]`. Confirm the litigant has approved the substantive version for rendering.
3. **Compose, render and validate, in that order.**
   1. From Court Filing run `node scripts/court-filing.js compose --body <body.md> --caption <caption.json> --profile <id-or-file> --out <fresh.html>` with absolute file arguments. Keep the resulting `html`, `profile`, `pdf`, `pdfArgs`, `footerFont`, `bodySha256` and `bodyWords`. Match `bodySha256` to the citation clearance before rendering.
   2. From the `wiser` tool `render` run `node scripts/render.js pdf --input <html> --output <fresh.pdf>` and append `pdfArgs` unchanged as individual arguments. Require a successful run with `output` at the intended path, `format` equal to `pdf`, and a concrete `pages` count. Keep the CSS page geometry and footer settings from the composition. If the renderer refuses the file, hold and resolve the named error before retrying.
   3. From Court Filing run `node scripts/court-filing.js validate --pdf <output> --caption <caption.json> --profile <id-or-file> --body-sha256 <compose digest> --body <body.md>` with the same inputs. Pass `--limit <id>` for the applicable preset, or pass `--max-pages <N>` and/or `--max-words <N>` for explicit maxima. For verified inapplicability pass `--no-length-limit <reason>` with the controlling basis. Require exit 0, `ok: true`, and exactly `result: "ALL CHECKS PASSED"`. Match `profile`, `bodySha256`, and the reported `limits.choice` and values to the selected inputs. Read `pages`, `bodyWords`, `pdfBodyWords`, `checks` and `unavailable`. Require all applicable checks to pass, including composed and printed body binding, PDF length when limited, the correct caption and signature blocks, and certificate treatment. Accept certificate `not_applicable` with a passing absence check and a verified document treatment or an exact approved profile reason. For a required blank case number, require the named blank-field check to pass. On exit 1, read stderr for the failure and retain it in the build record. Hold on any failed or unmeasurable check, absent length choice, or mismatched input. Changes to the text or cited attachments reopen citation clearance.
4. **Handle a required Word or official form.** Does the court or document require `.docx`? For a new Word artifact that fits the documented title-and-paragraphs format, use `node scripts/word-document.js create --input <json> --output <fresh.docx>` from `wiser`'s `word-document` directory. The UTF-8 JSON supplies `title` and `paragraphs`. Require a successful result with the intended canonical `output`. For a required caption table or other structure outside the create schema, use the court's official Word template or require a Word artifact that can meet those requirements. Hold if the prescribed structure cannot be produced or checked. Inspect the actual Word file and apply any court-mandated mechanical checks. For a filing, retain a mechanically validated court PDF proof using steps 2 and 3 and compare it with the Word submission, including caption, legal text, page structure and certificates. Hold release if equivalent content and applicable court requirements cannot be established. For a required official fillable form, obtain it from the issuing court, fill the original form and check its required fields and applicable packet rules. If Open a Matter handed over just the Colorado district civil complaint, return that artifact to it for JDF 601, JDF 600 and fee or waiver checks. For a direct request for that entire packet, route to Open a Matter. Use a legacy table caption only as a visual reference when supplied. Generate new motion PDFs with steps 2 and 3.
5. **Review the exact artifact with the litigant.** Rasterize PDF pages to PNGs in the build folder using available local PDF tooling, such as `pdftoppm -png`. Open the pages and visually check caption, spacing, page numbers, margins, exhibits, signature lines and the declared certificate treatment, including whether the finished filing correctly omits the certificate. If the preview cannot be produced or differs from the profile or draft, hold the filing and resolve it. Show the artifact and intended submission, recipients and attachments. The litigant signs their own documents and completes applicable blank signature and service dates immediately before filing in a PDF editor or by the court's accepted method. Verify the planned filename date against actual filing or service. If only the signature or date fields change, mechanically validate the exact final PDF with the same body binding, caption, profile and length choice, and repeat the affected visual checks. If the body, its citations or cited attachments change, rerun Verify Citations on the exact revised inputs, then recompose, rerender and revalidate before review. If the editor strips the body binding from a signature/date-only edit, use a court-accepted method that preserves it, or hold the artifact. Never insert signature or service dates by automation.
6. **Record release and filing separately.** Apply the Litigation Counsel owner gate under `wiser/AGENTS.md` Precedence and routing before any filing-ready handoff, subject to its separate-review decline path. Carry any preflight hold even when that review is declined. Is the exact reviewed packet explicitly approved for transmission with all applicable gates passed? If yes, the litigant can file through the forum’s approved channel, including Colorado Courts E-Filing where applicable, or give a specific instruction to transmit the exact shown packet where permitted. If approval is absent, return the validated artifact for the litigant's review. A draft approval, a signature or a promised future approval cannot authorize transmission. After the litigant reports filing or supplies the court receipt, use Maintain Matter File to record the actual date and update the matter. Retain previews and build sources as scratch under the matter's retention rules.

## Pitfalls

- A vague document, conflicting jurisdiction, or unclear date needs clarification before rendering. A date slip calls for updating the visible filename and reviewing any date-dependent fields.
- Mechanical checks cover what the tool reports. Inspect what remains visual, including exact spacing and margin geometry, and escalate an unmet court requirement. Report tool or profile defects to their owning tool. Never patch the tool during filing production.
- Colorado's e-filing channel, a completed signature block and a preview can each exist before filing. Record filed status only when supported by confirmation.

## Success

The output path is visible and keeps any previously filed copy intact. The build record identifies the exact citation clearance, verified caption sources, compose and render inputs, validation result, preview review and human decision. No filing can be released with a held gate or recorded as filed without confirmation. Ask the litigant to report back after filing so the matter file can be updated.
