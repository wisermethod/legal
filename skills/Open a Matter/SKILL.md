# Open a Matter

## Context

Use for "new case," "set up a case for," "file a new case," "start a lawsuit," "open a case" or "draft a complaint" in the litigant's own matter. Apply the legal constitution's Standing constraint. The matter record can hold any confirmed jurisdiction. The initiation procedure below covers Colorado district court civil cases of the class described in the court's current profile. Use Take Over a Matter for a populated legacy case folder.

Classifier seam: none.

## Objective

Create the matter's project and initialize its record. For an in-scope filing request, produce a reviewed initiation packet and, when the litigant reports filing and service, record the assigned number, proof and resulting deadlines.

## Inputs

- `<user_request>` identifies the scope, matter name, intended outcome and owning root or request for a dedicated user root.
- `<context>` provides known court or forum, jurisdiction, venue, procedural posture and filing build location. A records-only request can start before forum selection.
- `<source_material>` provides parties and contacts, claims and facts, evidence and dates, any prior case action, service information and current rules or official forms.

## Steps

Give the [Handoff label](../../AGENTS.md#handoff-label) in the handoff message whenever this work returns an assessment, packet or draft to the person, including on an early return. Never write it inside a document.

### What can proceed on this entry?

Follow [Litigation Counsel's preflight contract](../../experts/Litigation%20Counsel/EXPERT.md#how-does-a-skill-request-and-apply-preflight) before dependent work.

### What does this matter need to open?

1. **Place the project.** Which user root owns this matter under `wiser/standards/user-root.md` C3 and C4? In an existing owning root use `work/<slug>/`. If the person wants a dedicated user root for one matter, hand the root request to `wiser`'s Onboard Root by name, then use that root's `work/<slug>/`. If ownership or the destination is unsettled, ask before writing. Is the project path unoccupied, an established project for this case, or occupied by other material? For an unoccupied path, once the destination is settled, ask the questions in [forum-questions.md](forum-questions.md) as directed there. Copy the bundled `assets/matter-template/AGENTS.md` and record each answer with its source and date under `## Forum and posture`, using the template's field values and claim table. Complete the project `AGENTS.md` with the template’s single startup order, the glossary designation or statement of absence, posture, authoritative paths, retained file map and the owner’s completion condition or pending choice. Only then copy the other bundled template files. Which forum does the declaration name in `Court or forum`? In the `DEADLINES.md` copy, keep `## Working response periods` with only the `Colorado state` row for a Colorado state court or only the `Federal court in Colorado` row for the federal district court for Colorado. For every other or `pending` forum, omit the section. If a later declaration names a forum with a matching row, use the bundled template to add or update the section with that row alone and preserve the deadline register. Read back the file set and keep the root declaration in the root. For a confirmed project for this case, read its declaration and use the current files. For a legacy case folder, use Take Over a Matter. For any other collision, stop and confirm a different destination before copying.
2. **Initialize the supplied facts.** For an existing matter, start with Maintain Matter File in preflight mode. Preserve confirmed entries and route updates to existing dates and events through its applicable operation. In a new record, populate the parties and service contacts, claims as asserted, facts, supporting records, amount, initial history, deadline rows in the template’s register shape and arguments narrative and positions. Identify each source and distinguish confirmed facts from reported or unknown ones. Enter an unknown forum, claim element or limitations basis as pending. Ask about any fact needed to resolve a potentially urgent date and surface it before returning the record. In history, or the matter's designated status record, record prepared, filed, accepted and served separately. Identify what has been prepared, use a dated filing confirmation for filed, use the acceptance record and assigned number for accepted, and use proof for served. Name which events and dates are still unconfirmed or untriggered. Update these states only when their evidence arrives.
3. **Decide whether the filing route applies.** What did the litigant request?
   - **Record setup or intake only.** Return the initialized record and rule findings, with unresolved forum, authority and deadlines visible. When Pleadings requested intake, that skill owns any subsequent draft.
   - **Unclear scope.** Ask whether the litigant wants record setup, a complaint draft or a filing packet. Hold drafting and production pending the answer.
   - **Complaint draft or initiation packet.** Which forum did the person request? When the request names no forum, use the declaration's `Court or forum` and `Forum type` and take the **Unclear forum or district eligibility** branch after the conflict check below if `Court or forum` is `pending`. When the request names no forum and the declaration is missing, report the missing declaration and use the forum established from the record in the preflight finding. Verify any conflict before dependent work. A contract clause, demand or notice that sends the dispute to arbitration or to any forum other than the one requested is such a conflict. Hold on this bullet, before any branch below: name the clause, demand or notice and what it requires, and ask whether the person will follow it or contest it. Until that choice and the controlling text, or the demand or notice itself where there is no clause, are in the record, run no profile lookup, inventory no court packet and write no draft. Record the choice in the matter’s history. When the person follows it, take the branch below that matches the forum it names: the Colorado district branch where that is the forum, and otherwise the outside branch. When the person contests it, take the branch for the forum the person requested.
     - **Outside the Colorado district procedure.** For a county court, small claims, federal court, other state or non-court forum, state the scope gap and end the district route here. On this branch never run the profile lookup or steps 4 through 7, and never write `body.md` or a `new-case-complaint` caption. For a full initiation request, return the initialized record, known dates and verified forum requirements. Include an inventory of initiation instructions and missing rules or forms for a non-court forum. For a complaint draft only, where the forum is a court outside the Colorado district procedure, verify the forum through Venue Selection and apply the pleading checks below. If they permit drafting, hand the intake and verified forum to Pleadings, which owns the draft, and write no draft here. Where the forum is not a court, whether a clause, a demand or a notice put the matter there, write no court complaint and hand none to Pleadings: return the initialized record and name the forum’s own initiating submission as the paper to prepare by the non-court route in the next sentence. For a separately requested non-court submission, route to Pleadings or Draft Motion by document type after its drafting prerequisites clear. Use Produce Court Filing for that artifact only after its gates clear.
     - **Colorado district civil case.** Verify the forum, jurisdiction, venue and applicable amount in controversy through Venue Selection and the current rule. Confirm the working threshold of over $25,000 for the profiled class of cases. If eligibility remains unconfirmed, use the next branch. If the verified case falls outside the profiled class, return the initialized record and explain the scope gap without entering step 4. Otherwise apply the pleading checks below. If they permit drafting, read the profile and continue to step 4. Open a Matter owns the complaint on this route.
     - **Unclear forum or district eligibility.** If the forum is unclear, use Venue Selection to identify it before choosing a branch. If the forum or district eligibility remains unconfirmed, ask for the missing facts or authority and return the initialized record with any held requirements checklist. For a proposed Colorado district packet, use the profile lookup below only to inventory requirements. End this branch before drafting, form completion or production.

   **Can the affected pleading be drafted?** Use the practice-area assessment and Claim Chart where element support is needed. Verify each claim’s elements and limitation period, trigger and relevant dates. If the period, trigger or dates are unresolved, or a time bar is possible, flag the risk of dismissal or sanctions, suggest limited-scope counsel or document review, and name the evidence needed to clear the hold. This is a drafting hold, on every branch: while the period, trigger or a relevant date is unresolved, or a time bar is possible, do not write `body.md`, hand off the pleading or run steps 4 through 7. Apply any other preflight holds to the work they affect. When drafting is held, return the initialized record with the supported preparation, risk flags and resumption evidence. End this branch before writing `body.md`, handing off the pleading or running steps 4 through 7. A hold limited to filing readiness stays in force while independent review drafting proceeds. A limitations hold is never limited to filing readiness.

   **Profile lookup.** Colorado district branch only, after eligibility is confirmed and the pleading checks permit drafting. The unclear-eligibility branch above reads the same packet only to inventory requirements and drafts nothing. Read the Court Filing tool contract and run `node scripts/court-filing.js profiles` from its directory. In `profiles`, select `jurisdiction_id: "colorado-district"` and read `filing_packets.new_case_complaint`.
4. **Build the district complaint.** Use Pleadings as a requirements reference, including the C.R.C.P. 8 check where it governs. If the litigant supplies a complaint that meets the verified requirements, use that exact draft. If a new draft is needed, write it here using Draft Motion’s Document registers and Filing prose checklist. Use Draft Motion for any separately requested motion. Use `body.md` for numbered supported factual allegations, separate counts with required elements, a jury demand when applicable and the prayer for relief. Read it aloud in a plain, informed self-represented voice. Preserve necessary pleading structure and correct citation form. Verify the court's AI disclosure requirements where applicable. Build `caption.json` from sourced intake and the Court Filing profile. Declare `document_type: "new-case-complaint"` and `filing_packet: "new_case_complaint"`. Leave `case_number` empty for assignment by the court. Use the assigned division or leave `division` empty when the confirmed court instructions accept an unassigned division. Apply the [initial complaint certificate check](#what-can-the-initial-complaint-certificate-state) to source the required `service` fields and determine what can be released. Run Verify Citations with the exact body and its cited-attachment manifest and resolve all `[verify]` flags.

   **What is the requested output?** For a draft only, return the draft with any holds and end the route. For a review artifact or initiation packet, check the certificate, citation and production prerequisites. Use the profile’s null `length_presets` with no length flags when the record supplies no maximum. If the record identifies a possible maximum, verify the governing rule or order. Hold production until the type and sourced limit reconcile or the evidence establishes that no maximum applies. If a prerequisite remains held, return the draft and the evidence needed to clear the hold. Otherwise hand the approved draft, caption, clearance, manifest and exact attachments to Produce Court Filing for the complaint only. Court PDF validation and human review are mandatory before filing. If production fails, return the held result. If the validated complaint is the requested review artifact, return it and end the route. For a full initiation packet with a validated complaint, continue to step 5.
5. **Prepare official forms and fees.** For an initiation packet, confirm current applicability and requirements with the Colorado Judicial Branch's authoritative materials, including current copies supplied by the litigant. Use its official fillable PDFs for JDF 601 District Court Civil Case Cover Sheet, associated with the initial pleading under C.R.C.P. 16.1 when applicable, and JDF 600 District Court Civil Summons. Fill every required field on the provided PDFs after the forum and form requirements are confirmed. Confirm the fee amount and, for a waiver, the current motion and financial affidavit forms `[verify]`. Which route did the litigant choose? If paying, include the fee as verified. If seeking waiver, include the verified motion and affidavit. If undecided, ask which route they want and hold completion of the packet. If any required fee, form or information remains unresolved or inaccessible, return the held packet checklist naming its source, what's missing and what to provide or verify. Use the court's original forms for the cover sheet and summons.
6. **Filing and service.** Before filing, verify the working 63-day interval for service after filing, the permitted method and proof under C.R.C.P. 4 and any order, and the applicable C.R.C.P. 12 answer period and computation basis below. If any is unresolved, hold filing. Show the validated complaint, official forms, payment or waiver materials, exact destination and attachments together. Apply Produce Court Filing’s exact-artifact preview and release steps to the entire packet, including the official forms’ sourced requirements gate. Record explicit approval against the hashes of the files shown. Recheck the hashes before any transmission. The litigant uses Colorado Courts E-Filing (CCEF) for an approved packet where applicable. On filing confirmation or receipt, route the confirmed filing to Maintain Matter File. On acceptance, update the parties record, caption and other affected case records with the assigned number. Have the litigant arrange service and file the return or proof after service. Apply Produce Court Filing's applicable gates before any filing or service transmission. Use [Returning the work](../AGENTS.md#returning-the-work) for the filing-draft handoff. Ask the litigant for the filing confirmation and, separately, for the proof after service.
7. **Seed deadlines.** After actual service, pass the proof to Maintain Matter File’s **Service confirmed** operation for location, date and method. Check the facts against the verified C.R.C.P. 12 calculation basis. The working Colorado district civil defaults are 21 days after in-state service and 35 days after out-of-state service. Use the applicable trigger, exceptions, time computation and any order. If service facts or calculation inputs remain uncertain, keep that deadline pending. Record case management, discovery and other deadlines as they arise. Route any confirmed proof filing to Maintain Matter File for history, index and deadline updates. If filing or service is still pending, list which dates are untriggered or awaiting confirmation.

### What can the initial complaint certificate state?

The Colorado district profile prints a certificate. Check the operative court instructions for what document delivery, if any, it certifies at initial filing. State only facts the signer can attest to about the identified document, recipient, permitted method and actual date of any delivery made. A blank date on a review draft is for later completion against actual evidence. If initial Rule 4 service is still ahead, leave it in the service plan and record its later proof separately. If the governing instructions do not resolve what can appear in the profiled certificate before process is served, return the draft or checklist held and name the court form, rule or authoritative direction needed for a truthful certificate or an accepted alternate procedure.

## Pitfalls

- An ambiguous name, scope, owning root or jurisdiction needs clarification before the dependent step. A request to draft or open a record does not authorize filing, paying or serving.
- Official forms may change. If the required official form cannot be obtained or checked, report the missing form and hold the packet. Never recreate a JDF form in Word or the filing renderer.
- A dormant or uncertain limitations date is consequential. Keep the basis and verification state in the deadline record and surface imminent or missed fatal dates first.

## Success

The project `AGENTS.md` names its record, startup order, glossary status and completion condition or owner question. Intake files reflect sourced facts. A completed in-scope packet has a citation-cleared and validated complaint, current official forms and a verified payment or waiver route. For a held request, the labeled handoff names the supported work, each unavailable item and the evidence needed to proceed. The file distinguishes prepared, filed, accepted and served states and records only supported dates and triggered obligations.
