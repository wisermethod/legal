# Open a Matter

## Context

Use for "new case," "set up a case for," "file a new case," "start a lawsuit," "open a case" or "draft a complaint" in the litigant's own matter. Apply the legal constitution's Standing constraint. The matter record can hold any confirmed jurisdiction. For initiation coverage, use the forum-file list in step 3. Use Take Over a Matter for a populated legacy case folder.

Classifier seam: none.

## Objective

Create the matter's project and initialize its record. For an in-scope filing request, produce a reviewed initiation packet and, when the litigant reports filing and service, record the assigned number, proof and resulting deadlines.

## Inputs

- `<user_request>` identifies the scope, matter name, intended outcome and owning root or request for a dedicated user root.
- `<context>` provides known court or forum, jurisdiction, venue, procedural posture and filing build location. A records-only request can start before forum selection.
- `<source_material>` provides parties and contacts, claims and facts, evidence and dates, any prior case action, service information and current rules or official forms.

## Steps

Give the [Handoff label](../../AGENTS.md#handoff-label) in the handoff message whenever this work returns an assessment, packet or draft to the person, including on an early return. Never write it inside a document.

### What can proceed on this entry?

Follow [Litigation Counsel's preflight contract](../../experts/Litigation%20Counsel/EXPERT.md#how-does-a-skill-request-and-apply-preflight) before dependent work. For an existing matter's pack-only request, use [the own rules set step](#how-does-a-matter-keep-its-own-rules-set) and return its findings. If the person wants a pack for a new matter, use that step after steps 1 and 2, when the declaration is on disk. Then choose the filing route in step 3.

### What does this matter need to open?

1. **Place the project.** Which user root owns this matter under `wiser/standards/user-root.md` C3 and C4? In an existing owning root use `work/<slug>/`. If the person wants a dedicated user root for one matter, hand the root request to `wiser`'s Onboard Root by name, then use that root's `work/<slug>/`. If ownership or the destination is unsettled, ask before writing. Is the project path unoccupied, an established project for this case, or occupied by other material? For an unoccupied path, once the destination is settled, ask the questions in [forum-questions.md](forum-questions.md) as directed there. Copy the bundled `assets/matter-template/AGENTS.md` and record each answer with its source and date under `## Forum and posture`, using the template's field values and claim table. Complete the project `AGENTS.md` with the template’s single startup order, the glossary designation or statement of absence, posture, authoritative paths, retained file map and the owner’s completion condition or pending choice. Only then copy the other bundled template files. Use [the working response periods step](#how-are-working-response-periods-seeded) for the `DEADLINES.md` copy. If a later declaration names a forum, apply that step to update only `## Working response periods` and preserve the deadline register. Read back the file set and keep the root declaration in the root. For a confirmed project for this case, read its declaration and use the current files. If its `AGENTS.md` has no field table under `## Forum and posture`, ask the questions in [forum-questions.md](forum-questions.md), show the person that section filled with each answer and its source and date, and add it only on their approval, changing nothing else in the file. For a legacy case folder, use Take Over a Matter. For any other collision, stop and confirm a different destination before copying.
2. **Initialize the supplied facts.** For an existing matter, start with Maintain Matter File in preflight mode. Preserve confirmed entries and route updates to existing dates and events through its applicable operation. In a new record, populate the parties and service contacts, claims as asserted, facts, supporting records, amount, initial history, deadline rows in the template’s register shape and arguments narrative and positions. Identify each source and distinguish confirmed facts from reported or unknown ones. Enter an unknown forum, claim element or limitations basis as pending. Ask about any fact needed to resolve a potentially urgent date and surface it before returning the record. In history, or the matter's designated status record, record prepared, filed, accepted and served separately. Identify what has been prepared, use a dated filing confirmation for filed, use the acceptance record and assigned number for accepted, and use proof for served. Name which events and dates are still unconfirmed or untriggered. Update these states only when their evidence arrives.
3. **Decide whether the filing route applies.** What did the litigant request?
   - **Record setup or intake only.** Return the initialized record and rule findings, with unresolved forum, authority and deadlines visible. When Pleadings requested intake, that skill owns any subsequent draft.
   - **Unclear scope.** Ask whether the litigant wants record setup, a complaint draft or a filing packet. Hold drafting and production pending the answer.
   - **Complaint draft or initiation packet.** Which forum did the person request? When the request names no forum, use the declaration's `Court or forum` and `Forum type` and take the **Unclear forum or eligibility** branch after the conflict check below if `Court or forum` is `pending`. When the request names no forum and the declaration is missing, report the missing declaration and use the forum established from the record in the preflight finding. Verify any conflict before dependent work. A contract clause, demand or notice that sends the dispute to arbitration or to any forum other than the one requested is such a conflict. Hold on this bullet, before any branch below: name the clause, demand or notice and what it requires, and ask whether the person will follow it or contest it. Until that choice and the controlling text, or the demand or notice itself where there is no clause, are in the record, run no profile lookup, inventory no court packet and write no draft. Record the choice in the matter’s history. When the person follows it, use the forum it names. When the person contests it, use the forum the person requested. Apply the branch below only to the forum established by the current preflight finding after any conflict is resolved.
     - **Outside the covered initiation procedure.** For an established court whose forum file is outside the list below, a court with no forum file, or an established non-court forum, state the scope gap and end the packet route here. For a court name its own initiation rules, filing instructions and official forms as the sources to obtain. On this branch never run the profile lookup or steps 4 through 7, and never write `body.md` or a `new-case-complaint` caption. For a full initiation request, include the initialized record, known dates and verified forum requirements in the handoff. Include an inventory of initiation instructions and missing rules or forms for a non-court forum. If the court’s forum file holds a prescribed-form or initiating-form statement, report it under [Forum procedure](../AGENTS.md#forum-procedure) with its source, state and last-read date before applying any drafting hold. For an outside court, verify the forum through Venue Selection and apply the pleading checks below when the request is for a complaint draft or for initiation in Colorado county court or small claims. If they permit drafting, hand the intake and verified forum to Pleadings, which owns the draft, and write no draft here. Where the forum is not a court, whether a clause, a demand or a notice put the matter there, write no court complaint and hand none to Pleadings: return the initialized record and name the forum’s own initiating submission as the paper to prepare by the non-court route in the next sentence. For a separately requested non-court submission, route to Pleadings or Draft Motion by document type after its drafting prerequisites clear. Use Produce Court Filing for that artifact only after its gates clear.
     - **Court with covered civil initiation requirements.** The covered forum-file list, by pack and forum ID, is the shipped `colorado` / `district-court`. Does the preflight finding name a file on that list? If yes, verify the forum, jurisdiction, venue and applicable amount in controversy through Venue Selection and the current rule. Read the file's civil jurisdiction and amount statements under [Forum procedure](../AGENTS.md#forum-procedure). Use a `[verify]` jurisdiction or amount statement with its state shown. For an initiation packet, list every applicable initiation statement from the file in the requirements checklist under Forum procedure, even when drafting or filing is held. For this routing decision, eligibility is unconfirmed only when a needed fact or statement is missing. When a needed statement is missing, name the court's own jurisdiction and venue rules as sources to obtain and hold the eligibility check. If eligibility remains unconfirmed, use the next branch. If the verified case falls outside the applicable initiation requirements, return the initialized record and explain the scope gap without entering step 4. Otherwise apply the pleading checks below. If they permit drafting, use the profile step and continue to step 4 within its holds. Open a Matter owns the complaint on this route. If the court is established and the answer to the coverage question is no, use the outside branch.
     - **Unclear forum or eligibility.** If the forum is unclear, use Venue Selection to identify it before choosing a branch. If the forum or eligibility remains unconfirmed, ask for the missing facts or authority and return the initialized record with any held requirements checklist. For a proposed packet in the covered court, use the profile lookup below only to inventory requirements when the declaration supplies a compatible profile. End this branch before drafting, form completion or production.

   **Can the affected pleading be drafted?** Use the practice-area assessment and Claim Chart where element support is needed. Verify each claim’s elements and limitation period, trigger and relevant dates. If the period, trigger or dates are unresolved, or a time bar is possible, flag the risk of dismissal or sanctions, suggest limited-scope counsel or document review, and name the evidence needed to clear the hold. This is a drafting hold, on every branch: while the period, trigger or a relevant date is unresolved, or a time bar is possible, do not write `body.md`, hand off the pleading or run steps 4 through 7. Apply any other preflight holds to the work they affect. When drafting is held, return the initialized record with the supported preparation, risk flags and resumption evidence. End this branch before writing `body.md`, handing off the pleading or running steps 4 through 7. A hold limited to filing readiness stays in force while independent review drafting proceeds. A limitations hold is never limited to filing readiness.

   **Profile lookup.** Use this step on the covered route after eligibility is confirmed and the pleading checks permit drafting. The unclear-eligibility branch above reads the same packet only to inventory requirements and drafts nothing. Which `Filing profile` does the declaration give? For a declared profile ID or path, read the Court Filing contract, run `node scripts/court-filing.js profiles` from its directory and check the declared candidate against the court using Produce Court Filing's profile checks. Read the compatible profile's initial complaint type and packet. If the value is `pending`, report any forum file `filing_profile` as a suggestion and hold the profile-dependent work until the declaration is settled. If the declaration is absent, report that gap. If it names no profile or the candidate is incompatible, use the court's own prescribed or unprofiled format through Produce Court Filing when verified. If that format is missing, name the court's own filing instructions as the source to obtain and hold format-dependent work.
4. **Build the complaint.** Use Pleadings as a requirements reference. Read the forum file's complaint pleading statement under [Forum procedure](../AGENTS.md#forum-procedure). If the file or statement is missing, name the court's own complaint pleading rule as the source to obtain and hold drafting dependent on it. If the litigant supplies a complaint that meets the verified requirements, use that exact draft. If a new draft is needed, write it here using Draft Motion’s Document registers and Filing prose checklist. Use Draft Motion for any separately requested motion. Use `body.md` for numbered supported factual allegations, separate counts with required elements, a jury demand when applicable and the prayer for relief. Read it aloud in a plain, informed self-represented voice. Preserve necessary pleading structure and correct citation form. Verify the court's AI disclosure requirements where applicable. For a compatible profile, build `caption.json` from sourced intake and the profile. Where it lists the `new-case-complaint` type and requires `new_case_complaint`, declare those IDs. Leave `case_number` empty for assignment by the court when the type requires a blank. Use the assigned division or leave `division` empty when the confirmed court instructions accept an unassigned division. Apply the [initial complaint certificate check](#what-can-the-initial-complaint-certificate-state) to source the required `service` fields and determine what can be released. On the verified prescribed or unprofiled path, use the court's sourced submission fields. Run Verify Citations with the exact body and its cited-attachment manifest and resolve all `[verify]` flags.

   **What is the requested output?** For a draft only, return the draft with any holds and end the route. For a review artifact or initiation packet, check the certificate, citation and production prerequisites. For a profile type with null `length_presets`, use no length flags when the record supplies no maximum. If the record identifies a possible maximum, verify the governing rule or order. Hold production until the type and sourced limit reconcile or the evidence establishes that no maximum applies. If a prerequisite remains held, return the draft and the evidence needed to clear the hold. Otherwise hand the approved draft, caption or sourced submission fields, clearance, manifest and exact attachments to Produce Court Filing for the complaint only. Court PDF validation is mandatory for a compatible profiled PDF. Human review is mandatory before filing. If production fails, return the held result. If the validated complaint is the requested review artifact, return it and end the route. For a full initiation packet with a validated complaint, continue to step 5.
5. **Prepare official forms and fees.** For an initiation packet, use the forum file's statements on the cover sheet, summons, current fee, cost waiver, waiver forms and payment or waiver submission under [Forum procedure](../AGENTS.md#forum-procedure). Identify any dated fee separately from the current fee. Confirm current applicability and requirements with the court's own rules, filing instructions, official forms and fee schedule, including current copies supplied by the litigant. When the file or a required statement is missing, name the corresponding court source and hold that check. Fill every required field on the supplied official forms after the forum and form requirements are confirmed. Which route did the litigant choose? If paying, include the fee as verified. If seeking waiver, include the verified motion and affidavit. If undecided, ask which route they want and hold completion of the packet. If any required fee, form or information remains unresolved or inaccessible, return the held packet checklist naming its source, what's missing and what to provide or verify. Use the court's original forms for the cover sheet and summons.
6. **Filing and service.** Before filing, use the forum file's statements on the service interval, permitted methods, proof, answer periods and filing channel under [Forum procedure](../AGENTS.md#forum-procedure). Verify the applicable requirements and computation basis against the court's own rules and any order. If the file or a required statement is missing, name the court's own rules on that topic or filing instructions as the source to obtain. If any is unresolved, hold filing. Show the validated complaint, official forms, payment or waiver materials, exact destination and attachments together. Apply Produce Court Filing’s exact-artifact preview and release steps to the entire packet, including the official forms’ sourced requirements gate. Record explicit approval against the hashes of the files shown. Recheck the hashes before any transmission. Record the verified filing channel for the exact approved packet. On filing confirmation or receipt, route the confirmed filing to Maintain Matter File. On acceptance, update the parties record, caption and other affected case records with the assigned number. Have the litigant arrange service and file the return or proof after service. Apply Produce Court Filing's applicable gates before any filing or service transmission. Use [Returning the work](../AGENTS.md#returning-the-work) for the filing-draft handoff. Ask the litigant for the filing confirmation and, separately, for the proof after service.
7. **Seed deadlines.** After actual service, pass the proof to Maintain Matter File’s **Service confirmed** operation for location, date and method. Use the forum file's answer-period statement under [Forum procedure](../AGENTS.md#forum-procedure) and check the service facts against the verified basis. If the file or statement is missing, name the court's own answer and time-computation rules as the sources to obtain. Use the applicable trigger, exceptions, time computation and any order. If service facts or calculation inputs remain uncertain, keep that deadline pending. Record case management, discovery and other deadlines as they arise. Route any confirmed proof filing to Maintain Matter File for history, index and deadline updates. If filing or service is still pending, list which dates are untriggered or awaiting confirmation.

### How are working response periods seeded?

What court does the declaration name? For a new or changed declaration, ask Litigation Counsel for a current preflight finding based on that declaration before seeding. When planning a transfer, provide the proposed declaration as intake for the finding used in the plan. If `Court or forum` is missing, pending or conflicts with the controlling record, omit `## Working response periods` from a new copy and carry the gap or hold forward.

Does the finding for the declared court name a forum file with answer, motion-response or discovery-response statements? If yes, use the template's `## Working response periods` table. Write or update one row for the declared court, using its name in the `Court` cell. Keep each existing cell for that court when an applicable matter rule or order controls it; use the forum file's applicable statement for a cell the matter's rules and orders leave open. With each statement record its citation, URL when supplied, state and date read under [Forum procedure](../AGENTS.md#forum-procedure). If the file states no period for a cell, preserve its existing applicable sourced value for that same court. Where neither source supplies the period, enter `pending`, name the court's own rule on that topic as the source to obtain, and keep the dependent date pending. When no working response statement is available, preserve an existing applicable sourced row for the confirmed court; omit the section from a new copy and report the court's own response-period rules as the sources to obtain. Never carry a different court's periods into the declared court's row. A working row records sourced periods and their state. Put a due date in the deadline register only when the verified calculation and trigger support it.

### How does a matter keep its own rules set?

What has the person asked for, and what does the lookup say about the requested court, forum or claim's law? Use the first step that fits for each requested rule.

1. If the person asks the session to supply, complete or fetch rule text, write nothing for that rule and ask again for the exact words and the source, even for a covered court. Use only what the person supplies. State no rule from the session's memory.

   For a request that clears step 1, run `node scripts/jurisdictions.js resolve --matter <absolute-AGENTS.md>` from the Jurisdictions tool directory on the declaration as it now stands on disk, before any pack write.

2. If the row has `held: true` or an entry in `invalid_packs` names the requested court, forum or law through `matches` or the matter's records, report the hold and any failures and write nothing for that row. Also use this guard for an uncovered law when a failed manifest has no `matches` object, as in [Litigation Counsel's finding](../../experts/Litigation%20Counsel/EXPERT.md#what-matter-and-deadline-govern). Withhold any files from a held row.
3. If a valid match has `own_pack: true`, add the new passages to the pack at the returned `pack_directory`. Preserve existing passages and use distinct statement IDs and excerpt paths.
4. If a valid shipped pack covers it, return that finding and stop the pack step.
5. If the declaration or lookup is pending, missing or failed, or the applicable row is absent, report the gap and write nothing.
6. Otherwise, start a pack in the matter at `jurisdictions/<pack-id>/` when the applicable row has `status: "none"` with reason `no pack covers this court` or `no pack covers this law`. For any other result, report its reason and write nothing.

For a request that reaches a write path, ask the four [own pack questions](own-pack-questions.md#the-questions-asked-once-per-rule) as written. Apply step 1 again if a reply asks for rule text. Did the person supply and confirm any exact passage and its source? If none, end the step without a write. If at least one qualifies, record the qualifying passages in the chosen pack following the [Jurisdictions pack format](../../tools/Jurisdictions/schema/pack-format.md). When adding a match pattern, escape the leading law name alone for `law_match` so an exception still resolves as held. For `court_match`, remove any case or reference number as the [matching rules](../../tools/Jurisdictions/schema/pack-format.md#matching) describe and escape the court name. When a second pattern must match the case or reference number too, use the full declaration as an escaped literal. Put court and forum procedure in the forum half. Put a governing-law rule in `law/<area>.json` for the claim's area in Litigation Counsel's lens table, and create that law file only when the person supplied at least one rule for it. Use a confirmed Court Filing profile ID for `filing_profile` when the declaration supplies one and `null` otherwise. In `obtain`, list only sources the person identifies as still missing. Save each passage in an excerpt with `source.url` on the first line when present, otherwise `source.citation`. Put the date read on the second line in `YYYY-MM-DD` form. Mark a statement `Verified` only when the person supplied an official source and the saved passage supports the statement. Mark every other statement `[verify]`. Record the title and section in the statement's `source.citation`, and its link in `source.url` when the person gave one.

After writing the pack, ensure the matter's `## Matter record` table in `AGENTS.md` has one `jurisdictions/` row identifying it as the home of the matter's own rules packs. From the Jurisdictions tool directory, run `node scripts/jurisdictions.js validate --pack <dir>` with the pack directory's absolute path. On exit 1, read the JSON from stderr and report each failure. When validation passes, report any gaps and run `node scripts/jurisdictions.js stale --pack <dir>` from the same directory. Use the returned `prompts` array for the closing age prompts.

### What can the initial complaint certificate state?

Check whether the selected profile's initial complaint type prints a certificate or the court otherwise requires one. If neither does, record the sourced treatment and end this check. Check the operative court instructions for what document delivery, if any, it certifies at initial filing. State only facts the signer can attest to about the identified document, recipient, permitted method and actual date of any delivery made. A blank date on a review draft is for later completion against actual evidence. If initial service of process is still ahead, leave it in the service plan and record its later proof separately. If the governing instructions do not resolve what can appear in the profiled certificate before process is served, return the draft or checklist held and name the court form, rule or authoritative direction needed for a truthful certificate or an accepted alternate procedure.

## Pitfalls

- An ambiguous name, scope, owning root or jurisdiction needs clarification before the dependent step. A request to draft or open a record does not authorize filing, paying or serving.
- Official forms may change. If the required official form cannot be obtained or checked, report the missing form and hold the packet. Never recreate a court's official form in Word or the filing renderer.
- A dormant or uncertain limitations date is consequential. Keep the basis and verification state in the deadline record and surface imminent or missed fatal dates first.

## Success

The project `AGENTS.md` names its record, startup order, glossary status and completion condition or owner question. Intake files reflect sourced facts. A completed in-scope packet has a citation-cleared and validated complaint, current official forms and a verified payment or waiver route. For a held request, the labeled handoff names the supported work, each unavailable item and the evidence needed to proceed. The file distinguishes prepared, filed, accepted and served states and records only supported dates and triggered obligations.
