# Maintain Matter File

## Context

Use at the start of any matter-specific session and for "I filed," "we received an order," "the opposing party filed," "audit the case files," "what are our arguments," or "what do we need in discovery." Apply the legal constitution's Standing constraint. This skill maintains the matter's records. Case Audit owns evaluation of the whole litigation position.

Classifier seam: none.

## Objective

Leave a checkable record of what happened, where the primary documents sit, what deadlines changed, and which questions still need review. For preflight and inventory-only work, return findings without committing proposed record edits.

## Inputs

- `<user_request>` names the matter and desired operation, such as preflight, drafting or research references, record update, inventory audit, argument consolidation, or discovery tracking.
- `<context>` names the owning root, the matter's `AGENTS.md`, current date and any glossary the owning root designates.
- `<source_material>` holds the reported action, dated document, receipt or communication, applicable orders or rules, and any research or evidence newly identified.

## Steps

Apply the [Handoff label](../../AGENTS.md#handoff-label) whenever this work returns an assessment, packet or draft to the person, including on an early return.

### What can proceed on this entry?

Follow [Litigation Counsel's preflight contract](../../experts/Litigation%20Counsel/EXPERT.md#how-does-a-skill-request-and-apply-preflight) before dependent work.

### Which matter record needs attention?

1. **Preflight before the request.** Read the owning root and matter declaration, then the binding matter rules and handoff in the declared order. Use the declaration's designated history, deadlines, indexes, glossary and writing conventions throughout. The template names are defaults for new matters. If a path conflicts or is undeclared, locate the existing authoritative record or report the unresolved choice before writing. Report each deadline within 14 days immediately, including what is due, the source and any uncertainty. Surface overdue or potentially fatal deadlines first and suggest licensed counsel for a missed or imminent fatal deadline. What is the state of the designated deadlines record? If current, check it against new supplied evidence. If stale, disclose it and reconcile against available orders, docket and dated service records. If missing, disclose it and check the same primary records for alerts, even when no deadline file can be written. Return proposed entries, sources and verification states for the missing record. Ask for the authoritative file or confirmation to restore the declared path before creating it. Continue independently supported updates to other records and include the pending deadline write in their read-back. If a new trigger could change a date, state the candidate with its basis and verification state and alert the litigant immediately if it may be urgent. Never mark a date satisfied without evidence. Do the same deadline check on resuming work. Resolve posture from the latest applicable dated entry and its underlying order, receipt, service or case-administration record. A later summary changes posture only where its evidence establishes a new operative event or supersedes the earlier entry. Retain conflicting readings and flag a stale Current Status for a sourced correction. When the live docket or forum administration record cannot be reconciled, return `local-only` with the sources and dates checked, missing reconciliation and any hold on dependent timing or readiness. Deliver independent records work with that label and leave live confirmation open. Use Litigation Counsel's forum finding for any procedural check.
2. **Choose the operation.**
   - **Preflight for drafting, procedural work or research.** Check the matter's case law, statutes, claims, arguments and discovery list. Read the designated glossary for defined terms, where present. If the owning root designates none, report that there is no bound glossary and continue the records preflight. Use the practice-area guidance from the preflight only where the requested work needs substantive judgment. Identify the applicable phase from the posture without starting a phase run on a preflight request, such as Pleadings, Discovery, Motions Practice, Settlement Negotiation, Trial Preparation, Venue Selection or Case Audit. Confirm the procedural posture from the history for response questions. Return the checked sources, dates and gaps to the caller.
   - **Deadline-only update.** Use for a newly learned obligation or a correction that needs no new event. Take the obligation, any existing row or identifier, due date or trigger, primary source locator, calculation or unresolved inputs, verification status and explicit authorization for the proposed write. Compare the obligation and trigger with the current record. Reuse an identical row. If one row is uniquely matched and an operative source resolves the change, update that row on approval. If the obligation is new and supported, add one row on approval. If competing readings remain, preserve both with their sources as a conflict and ask what will resolve it before changing the record. For an unresolved or ambiguous match, missing or unavailable destination, or absent approval, return the exact proposed entry, marked `[verify]` where evidence is unresolved. Change only the approved row in the declared deadline record. Preserve the order, index and history of the underlying event. Read back the row and its source. Report the outcome as `applied`, `unchanged` or `pending` with the read-back or proposal.
   - **Our filing.** Confirm the document name and actual filing date against the receipt, docket or supplied confirmation. If filing is unconfirmed, keep the report and missing confirmation in pending history and hold the actual filings index and dependent updates. For a confirmed filing with the copy available, preserve the copy under `YYYY-MM-DD - <Document Name>.<ext>` in the filings directory or reuse the exact copy already present. When a receipt or other confirmation identifies the filing but the copy is missing, record the confirmed date and receipt or docket locator in the filings index and history. Mark the file field as missing and request the exact filed copy. When the copy arrives, match it to the same receipt or docket identifier, confirm any uncertain match, and complete the existing entries. Use Event, Outcome and Documents in history. Update deadlines the evidence shows the filing created or satisfied and Current Status when posture changes.
   - **Court or forum order or ruling.** Which evidence arrived? If the order is available, confirm its issue date and preserve it in the orders directory as `YYYY-MM-DD - Order <Description>.<ext>`. Update the orders index, history with the ruling and implications, and Current Status. If only a notice identifies the event and date, record both in history and the orders index with the notice locator and missing-order note, and ask for the order. If the notice cannot identify the event, record the notice in pending history and ask which order it concerns. In every branch, apply a deadline only where the supplied primary evidence and governing rule support it. Ask whether the litigant wants to discuss next steps or implications. Explain evidence-based options and tradeoffs within the confirmed procedural posture when asked.
   - **Opposing party's filing.** Confirm the document and date. Preserve it in the filings directory as `YYYY-MM-DD - <Party> <Document Name>.<ext>`. Update the filings index and history. Determine whether a response is required and note any applicable verified deadline in the deadline record. Ask whether the litigant plans to respond, and show the verified date or say what remains unresolved. If response duty or date remains unclear, ask which response is contemplated and what authority or notice sets its deadline.
   - **Service confirmed.** Use dated proof or other authoritative confirmation to record the served document, actual date, method, recipient and location where it affects a deadline. Link the proof in history and the applicable index. If the proof was filed, use **Our filing** for that separate event and link it to the service record. Apply supported response deadlines, keep uncertain inputs pending and read back both event links and the deadline. A proposed or unconfirmed service action stays pending.
   - **Correspondence sent or received.** Capture date, direction, parties, subject, source and path in the correspondence index and history. Record any resulting deadline and update Current Status when affected. Drafted or scheduled correspondence stays distinct from a completed transmission.
   - **"Audit the case files" or "check for gaps."** Enumerate filings, orders, evidence and correspondence. Compare both ways with history and the applicable indexes. Report missing files, unindexed files, unsupported events, date mismatches and duplicate or broken links. Propose concrete fixes and apply them only on approval. For "how is the case going," "audit the case" or "evaluate our position," run Case Audit with the entire matter file set and evidence. Use its full method and bring the findings and prioritized actions back without substituting an inventory summary.
   - **"What are our arguments?" or "consolidate arguments."** Read claims and current arguments. Read both sides' filings for positions, attacks and rebuttals. Consolidate the narrative theme, each side's contentions, the cited evidence, weaknesses and open work in the arguments record. Link to the claims and original record rather than creating rival versions of facts. Retain abandoned or weakened arguments with their status.
   - **Discovery queue.** Use for "what do we need in discovery?" or "add to discovery list." Load the matter's discovery requests. Accept Discovery's verified category, reason, source, identification date, priority and confirmation. Preserve those values. For a directly identified need, classify it as a document request, interrogatory, request for admission, third-party subpoena or deposition and collect the same fields. Show additions and ask for approval where it is missing. Reuse an identical entry and read back each approved change. Return the exact pending entries when approval or the declared destination is missing. When any matter work reveals information needed from the other side, ask whether to add it.
   - **Different or unclear operation.** Ask which listed operation the person wants, keep deadline alerts visible and return before any write.
3. **Write and reconcile.** Respect the declaration’s file-shape rules. When one file owns dated facts, update that file once and link to it from other records. Apply generic history and filename patterns only where the owning matter uses them. What supports the update? If original records and reported facts agree, use the primary source and record the dates, source and status. If only the person's report is available, label the basis and any missing file or receipt. If records conflict, preserve both readings, flag the conflict and ask before changing a contested fact. Check existing paths and index entries before copying or appending. Reuse identical existing files and update one entry per event. If a path holds different bytes, preserve both and obtain a distinct path before adding the new copy. Keep orders' issuance, entry and service dates separate when relevant. Check rule version, trigger, applicable forum modification and calculation before treating a deadline as confirmed. Read back the changed paths, history links, indexes, deadline status and Current Status. Surface remaining gaps.
4. **Maintain reusable knowledge on confirmation.** Show the confirmed finding, its source and the exact proposed addition. Ask before writing it. Store case authority and statutes or rules in their designated matter records, and reusable definitions in the owning root’s designated writable glossary. If a glossary has no designated home, ask for one. Link evidence through the matter’s own evidence record. Use plain English, a precise definition where needed, typical context and the encounter date or source for glossary entries. When a reference is thin, research the gap and propose the supported addition in the matching writable record. Improvements to an expert’s reference material belong to the plugin maintainer.

### What should a phase do with a deadline?

Run the matter preflight at entry or reuse the current record for the same facts. Give its alerts before the phase analysis, including the consequences and immediate question for missed or imminent fatal deadlines. Re-alert when new evidence reveals urgency. Mark uncertain dates `[verify]` and hold readiness or timeliness conclusions that depend on them. For each learned or changed date, send the obligation, existing row if any, deadline or trigger, primary locator, calculation or open inputs, verification status and write authorization. Use the applicable event operation for a confirmed new filing, order or communication. Use **Deadline-only update** when the event is already recorded or the date has no new event. Include the read-back or exact pending entry in the phase packet. If the event write is unavailable or unauthorized, include the exact proposed entry with its source and status.

## Pitfalls

- If the matter, operation or destination is ambiguous, read the owning instruction chain first and ask before changing records. Blanket acceptance of recommendations does not confirm an undisclosed correction, discovery item or glossary addition.
- A source file is evidence. Keep its bytes intact and work from copies. Index the registered path and use links to the record's single source of truth.

## Success

The person sees upcoming and overdue deadlines before other work. A completed update identifies the original, the actual date and the applicable index, history and deadline entries. Read-back resolves those references or names the affected write and what will clear it. A preflight, ambiguous request or other held update returns a labeled handoff with its findings, pending edits, missing items, conflicts and any discovery or glossary additions awaiting approval.
